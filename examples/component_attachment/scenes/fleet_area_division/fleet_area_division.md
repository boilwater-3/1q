## 结论

**判定：通过**（FD 600 周期全链，无库问题、无场景问题）。本轮实测知识：

1. **切分计算全部在加载期完成**：场景 JSON 只声明 `platform`/`platforms[]`（原点/名字）与顶层 `mission_area`（一个区域 + 规划参数），切分 + 逐机规划在 `LoadSceneData` 内自动完成——路由表/区域可视化（route_plan/zones.csv 按 aircraft_id/name 分机）与手工分配场景零差异，demo 主循环无改动；
2. **条带几何与手算先验逐点吻合**：三机条带边界 29.990/29.999/30.008/30.017 无缝共享，扫描线纬度 = 条带起点 +250/+750 m（半间距偏移），每机 4 航点 = 2 线 × 2 端点；
3. **"分工覆盖"语义**：三机各自循环巡逻自己的条带（互不重叠），覆盖并集 = 整个区域——与"多机同航路重复覆盖"的本质区别在 1/3 的并行耗时与 3 倍覆盖效率；
4. **条带内扫描线位与整体规划略有差异（按设计）**：每机对**自己**的条带做半间距偏移（如 wingman_2 首线 30.01025 vs 整体规划 30.01013 量级），语义等价（各自条带全覆盖），预期表按条带手算为准；
5. **传感器通道行为与 fleet 先例同型**：目标在巡逻区内 → SAR squint 拒绝（FD 起飞转向段 1 个物理真实产品）、SBIRS 凝视质心偏离间歇、EOS 仅远距目标在窗内——切分覆盖对传感器无可观测差异（目标布局未变）。

**原型库回写**（`scenario_archetypes.md`）：编队切分覆盖 = 顶层 `mission_area`（单区域）+ `platforms[]`（只留原点/名字），加载器自动切分（多边形等宽条带 / 圆形同心环）→ 每机自动航路；与手工分配（fleet_patrol_multi_zone）可互换，可视化契约不变。
