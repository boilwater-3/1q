# SAR Session 内部显式校准请求工程契约

## 1. 目标

在不修改 public API、Session schema 和 replay 的前提下，冻结一个内部显式校准请求与
执行器契约。该请求由内部调用方明确指定标定目标、聚焦路径、图像像素和孔径来源，
执行器只消费已生成的未归一化聚焦结果并返回内部定标摘要。

## 2. 内部请求对象

每个请求至少包含：

- 非空 `request_id`
- 非空 `observation_id`
- `known_rcs_m2 > 0`
- `slant_range_m > 0`
- 指定 `image_row` / `image_col`
- `aperture_start_pulse_id <= aperture_end_pulse_id`
- 显式正 `weight`
- 显式聚焦路径：`RDA`、`GBP` 或 `BP`

请求必须由内部调用方构造。执行器不得从普通点目标列表、图像全局峰值或算法输出摘要
推断请求内容。

## 3. 执行时机

- 请求只在对应聚焦路径成功产生未归一化复图像后执行。
- 请求路径必须与实际图像路径一致。
- 同一次执行可接收一个或多个请求，并原子转换为观测与定标样本。
- 任一请求无效或路径不匹配时，整次校准失败，不生成部分定标结果。
- 校准失败不得影响原聚焦结果，也不得触发算法回退。

## 4. 首批算法支持

- 内部 L1 RDA：支持，调用方必须提供 RDA 图像中的指定像素。
- 内部 GBP：支持。
- 内部 BP：支持，且相同输入/像素请求应与 GBP 结果一致。
- L2 补偿 RDA：首批只允许作为显式实验输入，不声明通用辐射精度。
- public L3 BP Session：暂不接入，等待内部执行器验证后单独审批。
- CSA、Omega-K、Auto：不支持。

## 5. 输出摘要

内部执行结果至少包含：

- `valid`
- `request_count`
- `image_calibration_factor`
- `weight_sum`
- 每个请求的 `request_id`、`observation_id` 和辐射残差
- 失败原因枚举

首批失败原因：

- 空请求列表
- 请求字段无效
- 聚焦路径不匹配
- 图像无效或像素越界
- 归一化图像声明
- 观测转换失败
- 定标计算失败

## 6. 生命周期

- 执行器无状态，不缓存上一次定标结果。
- 输出摘要由调用方决定是否替换旧结果。
- 不定义跨周期过期、自动复用、runtime patch 或 replay。
- 不将内部请求注入当前 public `SarCycleInput`。

## 7. 首批验收矩阵

1. M1 GBP 与 BP 相同请求产生相同定标因子和零残差。
2. M1 RDA 显式请求可执行并记录相对 GBP 的定标因子差异。
3. 多请求显式权重融合结果与底层定标核心一致。
4. 路径不匹配、越界像素、归一化声明和无效请求原子失败。
5. 失败不修改聚焦图像和调用方已有摘要。
6. 联合干扰输入只记录残差，不冻结有效性阈值。

## 8. 实现边界

- 首批实现为 `src/sar/calibration` 内部无状态执行器。
- 不修改 `SarSession`、public header、FlatBuffers、trace 或 replay。
- 不增加自动目标选择、自动像素定位、主瓣积分或质量阈值。
- 不触发算法切换、降级、拒绝原成像结果或 Auto。

## 9. 后续审批

内部执行器完成后，再决定是否受控接入 `SarSession` 内部管线以及是否公开摘要级
diagnostics。
