# SAR Phase 4 工作难度评估报告

Date: 2026-06-23

## 1. 评估目标

`module_design.md` 把 Phase 4 定为「聚束/扫描 + 多视 + L2/L3 联动 + 真 GeoTIFF」,
状态「未启动」。本报告评估该阶段**实际落地难度**,为是否启动及如何分阶段提供依据。
评估方法:核查代码现状与目标差距、识别前置依赖、参考已有审计的冻结结论。

## 2. 总体结论

Phase 4 是 SAR 模块**迄今最重的阶段**,五项中有四项属于「新能力从零构建」,只有
L2/L3 联动是「现有能力的编排集成」。难度呈数量级差异,不应作为一个整体并行启动,
应按难度与依赖**串行分批**:

| 子项 | 难度 | 依据 |
|---|---|---|
| 真 GeoTIFF | 🔴 高(依赖引入 + 地理编码全链路) | 零地理依赖、零地理编码 |
| 多视(Multilook) | 🟠 中(独立新算法,但输入已有) | 完全不存在,但聚焦图像已可消费 |
| 聚束(Spotlight) | 🔴 高(RDA 需大改 + 新天线/轨迹模型) | RDA 硬编码 broadside,零 squint 处理 |
| 扫描(ScanSAR) | 🔴 高(多子带 + 拼接 + 独立 PRF) | 零基础,且依赖 Spotlight 的 squint 能力 |
| L2/L3 联动 | 🟢 中低(集成编排,非新算法) | L2/L3 个体已闭环,缺编排与一致性矩阵 |

## 3. 逐项评估

### 3.1 真 GeoTIFF(🔴 高难度)

**目标**:把聚焦图像从 local Cartesian 平面地理编码为带投影的真 GeoTIFF。

**现状差距**(已核查):
- 输出层 `ImageFormatter.cpp::WriteGeoTiffSidecar` 当前只写 `base.raw`(float32 交错)+ `base.json` manifest,**无任何地理编码**。
- 项目**零 GDAL/PROJ/libtiff/geotiff 依赖**(已 grep `conanfile.py`、`cmake/PackageManager*.cmake`、`third_party/` 确认)。
- 当前仅有 `scene_center_latitude/longitude_deg`(公共配置)和 `origin_lat/lon`(manifest 占位),**无 DEM、无地图投影、无斜距-地距转换**。

**难点**:
1. **依赖引入**:受 C++11 + Eigen 3.3.9 + VS2015 vendor 约束(`module_design.md:407`),GDAL/PROJ 是重量级 C 库,需评估 Conan/vcpkg 可用性与跨平台构建门(参考 HDF5 用 HighFive 条件编译的先例,但 GDAL 比 HighFive 重得多)。
2. **地理编码算法**:需要斜距→地距(RDG)或斜距→地理(RDG + 高程)映射,涉及 DEM 采样或平坦地球近似,全链路从零。
3. **投影语义**:需要冻结 EPSG/WKT 投影约定、datum、像素间距的地理含义。

**工作量估计**:依赖调研 + 条件编译框架(类似 HDF5 模式)+ RDG 转换 + 投影写入。
**前置**:需先开新契约冻结投影约定、依赖选型(GDAL vs 轻量 proj)、平坦地球 vs DEM 策略。

### 3.2 多视 Multilook(🟠 中难度)

**目标**:对聚焦图像或原始数据做方位/距离多视平均,以牺牲分辨率为代价降低相干斑。

**现状差距**(已核查):
- 全仓库 `multilook`/`multi_look`/`多视`/`number_of_looks` **零命中**(仅 `module_design.md` 提及)。
- 无视处理逻辑、无视数配置、无视叠加平均算子。

**难点**:
1. 多视是**独立新算法**,但输入(聚焦复图像 `SarFocusedImage`、或 raw history)已有,不依赖其它 Phase 4 子项。
2. 需冻结:视数定义、视重叠策略、幅度 vs 功率平均、边界处理、是否在距离-多普勒域分视。
3. 公共配置需新增 `looks` 字段,trace/replay 需保真。

**工作量估计**:中等。算法本身不复杂(加窗分视 + 平均),主要是配置/契约/测试闭环。
**前置**:独立,可最早启动,不阻塞其它子项。**这是 Phase 4 中最易先做的一项**。

### 3.3 聚束 Spotlight(🔴 高难度)

**目标**:支持聚束模式(天线持续照射同一场景区域,获得更高方位分辨率)。

**现状差距**(已核查,关键):
- **RDA 硬编码 broadside 假设**:`SarRda.cpp` 零 squint 处理(grep `squint` 仅命中 broadside 相位参考模式名);多普勒中心假设为 0。
- geometry 层 `DopplerComputationInput` 有 `squint_angle_rad` 字段且 `ComputeDopplerParams` 支持非零 squint(`fd_central=2v·sin(θ)/λ`),但**RDA 从不调用它**(见 `phase1_status_audit.md` 不一致 #2:`ComputeDopplerParams` 对 RDA 是死代码)。
- 无聚束轨迹模型、无方位孔径拼接、无聚束专用波束指向。

**难点**:
1. **RDA 必须大改**:补多普勒中心估计 + 二次距离压缩(SRC)+ squint 修正的方位匹配滤波。当前 7 步管线假设 broadside。
2. **天线指向模型**:`SarAntenna` 当前是固定 boresight,聚束需时变波束指向(方位扫描)。
3. **轨迹模型**:聚束需平台直线运动 + 天线反向跟踪场景中心,非现有 L1/L2/L3。
4. 冻结的 Omega-K 是聚束友好的算法,但被冻结【不再扩展】,不能用作聚束路径。

**工作量估计**:高。RDA squint 化 + 新天线轨迹模型 + 孔径管理 + 契约/测试。
**前置**:需先开聚束契约冻结波束指向策略、SRC 实现、与 broadside RDA 的兼容边界。

### 3.4 扫描 ScanSAR(🔴 高难度)

**目标**:多子带交替扫描,获得宽测绘带(牺牲方位分辨率)。

**现状差距**:零基础,且 ScanSAR 天然带 squint(各子带不同视角),**依赖 Spotlight 先解决 squint 处理能力**。

**难点**:
1. 多子带(burst)管理 + 各子带独立 PRF + 子带间拼接(避免缝隙/重叠伪影)。
2. ScanSAR 专用聚焦 SPECAN 或 ECSA 算法,非现有 RDA。
3. 公共配置需新增子带列表、burst 参数。
4. 依赖聚束阶段沉淀的 squint/波束指向能力。

**工作量估计**:高,且是 Phase 4 最重子项。
**前置**:**强依赖 Spotlight 先落地**。建议 ScanSAR 排在 Spotlight 之后。

### 3.5 L2/L3 联动(🟢 中低难度)

**目标**:L2 扰动轨迹 + L3 航路点轨迹 + 运动补偿 + BP/RDA 在 Session 层联动,形成
多保真度组合的可审计矩阵。

**现状差距**(已核查,这项最接近就绪):
- L2(扰动轨迹 + 一阶补偿)、L3(航路点 + BP public Session)**个体均已闭环**(见 `phase3_status_audit.md`)。
- 缺的是:**L2×L3 组合场景**(如 L3 航路点上叠加 L2 扰动)、**多保真度一致性矩阵**(L1/L2/L3 同场景跨算法对比的系统化证据)、**Session 层的保真度选择编排**。

**难点**:
1. 主要是**集成编排 + 测试矩阵**,非新算法。
2. 需冻结:L2/L3 组合的语义(L3 航路点 + L2 扰动叠加规则)、互斥策略(当前 L3 BP 与 L2 补偿互斥,见 `l3_bp_session_integration.md`)。
3. 需二阶运动补偿证据(但二阶补偿按审计有意冻结,见 `phase1_status_audit` / `phase3_status_audit`),故联动可能先停在一阶精度边界。

**工作量估计**:中低。个体已就绪,主要是契约 + 矩阵 + Session 编排。
**前置**:独立,可与多视并行启动。**这是 Phase 4 中最易先做的一项(与多视并列)**。

## 4. 依赖关系图

```
多视(独立)─────────────────────┐
L2/L3 联动(独立)───────────────┤── 可并行首批启动
                                │
聚束 Spotlight ──依赖──→ 扫描 ScanSAR   (串行,ScanSAR 需 Spotlight 的 squint 能力)
                                │
真 GeoTIFF(依赖聚焦图像,独立于模式)  ← 可随时启动,但需先解决 GDAL/PROJ 依赖引入
```

## 5. 建议的分批启动顺序

按「难度低 + 依赖少」优先:

1. **第一批(并行,中低难度)**:多视 + L2/L3 联动。两者独立、输入就绪、风险低,可快速产出可审计闭环。
2. **第二批(独立,高难度但路径清晰)**:真 GeoTIFF。先做依赖选型契约(GDAL vs proj)+ 条件编译框架 + RDG 转换,参考 HDF5 的 HighFive 条件编译先例。
3. **第三批(高难度,核心算法扩展)**:聚束 Spotlight。RDA squint 化 + 天线轨迹模型 + SRC。这是 Phase 4 的技术核心。
4. **第四批(最高难度,依赖 Spotlight)**:扫描 ScanSAR。多子带 + 拼接 + SPECAN/ECSA,在 Spotlight squint 能力之上构建。

## 6. 关键风险与约束

1. **冻结边界**:CSA、Omega-K、自适应选择(Auto)、辐射定标、PGA 闭环、二阶运动补偿均被设计层冻结【不再扩展】。Phase 4 任何子项不得依赖这些冻结能力。**聚束不能依赖冻结的 Omega-K**;**L2/L3 联动不能依赖二阶补偿**。
2. **审批门控**:本项目采用严格阶段审批模型,每个子项**必须先开新契约再实现**。本评估不构成任何子项的实现授权。
3. **vendor/平台约束**:GDAL/PROJ 引入需过 C++11 + Eigen 3.3.9 + VS2015 门,是真 GeoTIFF 的主要工程风险。
4. **性能门**:RDA 当前冻结在 1024×1024,GBP/BP 在 128×128。聚束/扫描可能需要重新评估尺寸门。
