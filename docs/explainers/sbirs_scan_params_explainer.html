把五个指向参数画成"装在转盘上的探照灯"，拖滑块看每个参数怎么改变那束光。数据纯属示意，比例未按真实。

先回答：scan_start_az_deg 明明能算出来，为什么还要人填？

因为"该看哪"是任务决策，不是技术推算。库只提供"云台 + 镜头"（按指令转动、按光学探测）， 它不知道——也不应该知道——你的卫星摆在哪个经度、目标会从哪片天飞来。这些只有做任务规划的人（也就是集成它的你）才有答案。

更根本的一条：传感器模型不许"开天眼"。如果库替你自动把视场对准目标，就等于用真值作弊—— 真实卫星的扫描方案是发射前由地面规划好写进去的，仿真要还原的正是这个流程：瞄准是输入，不是推导。

三星场景里的 154.8° 那组数，就是当年"场景作者"先定好三星摆哪、目标飞哪，再反算出来填进 JSON 的。 你集成时扮演的就是这个角色——为自己的几何，填自己的数。
