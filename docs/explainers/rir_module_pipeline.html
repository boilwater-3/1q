RIR 模块图解：哨兵的一班岗

按工作顺序走完一个识别周期：排班 → 喊与听 → 跟踪 → 识别 → 交班。前一张页面的「增益 / 波位」概念在这里全部变成代码。

图 1一步一帧：一个识别周期的四站流水线

怎么读：这是哨兵的一班岗总览。外部每个周期喂一次输入（RirCycleInput：这一帧的场景目标 + 平台姿态）， RirSession.Step() 内部按四站流水线走完：先排班（波束指哪）、再逐驻留喊与听（物理链）、然后认人（跟踪 + 识别）、最后交班（输出帧交给融合， 同时录制回放、写验收日志），随后进入下一帧循环。主持三堂课的是 RirController。

图 2排班表：三类驻留怎么分波束时间

怎么读：每个周期先组装驻留计划（RirDwellPlan），优先级固定：① 指定识别——算子点名"看那个目标"，波束直接指过去 （kDesignate，你弹道场景的入口，引导式搜索）；② 跟踪驻留——对库里已确认的航迹按预测位置回望一眼，防止跟丢（kTrack）； ③ 搜索波位——剩余时间按蛇形光栅犁地找新目标（kSearch，就是前面"波位网格"那张图）。扫描区上移动的游标演示一个周期内波束依次造访每个驻留。

图 3喊与听：一个驻留里的完整物理链

怎么读：这是"回波过门限才算探测到"的代码化身。上路：发射脉冲（峰值 1 MW、脉宽 13 μs，RirEmissionFactory）→ 穿过大气被吃掉一截能量（传播模型，还要查地球曲率会不会把目标挡住）→ 砸到目标，只有 RCS 那么大的"反光面积"弹回一小部分。 下路（回波）：接收机收到微弱回波 → 雷达方程把 SNR 账本算清（+功率 +增益 −距离稀释 −各种损耗，RirRadarEquations）→ CFAR 判决：信噪比过门限才算探测到、生成点迹交给跟踪；没过门限，这一格等于没看见。移动的光点演示能量走完全程。

图 4从点迹到航迹：连点成线，丢一帧别慌

怎么读：探测产出的只是一个个孤立的点迹。跟踪层做三件事：关联——用最优指派（LAPJV 求解器）判断哪个点属于哪个目标； 滤波——IMM/KF 把抖动的点修成平滑航迹；生命周期——连续命中若干帧才"建档"确认（防止把噪声鬼影当目标）， 中间丢一帧就按航迹外推"脑补"顶上，连续丢失多帧才"销档"（不轻易放弃真目标）。动画演示目标飞过扇区时点迹逐帧累积成航迹。

图 5识别积累：四个特派员量特征，多帧投票过门限

怎么读：识别层派四个"特派员"从回波里量特征：距离像（结构轮廓，分辨率由带宽 c/(2B) 决定）、RCS（块头）、 运动（速度/高度变化姿态）、极化（表面材质）——拼成一组"指纹"去档案库（RecognitionFeatureDatabase 模板库）比对打分 （RecognitionMatcher）。单帧分数低很正常，RecognitionTracker 做多帧积累投票：置信度一路爬升， 越过识别门限（acceptance_score）那一帧才正式上报"认出来了"。右图楼梯就是逐帧攒置信度的过程（数值为示意）。
