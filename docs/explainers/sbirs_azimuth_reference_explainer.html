SBIRS 方位基准图解 — kNadirRelative 和 scan_start_az_deg 到底什么关系

一句话：scan_azimuth_reference 决定"尺子"（刻度从哪里量起），scan_start_az_deg 是用这把尺子读出来的数。下面三张图依次讲：① 同一个方向、两把尺子的读数对照；② 三颗星怎么"编舞"才能同周期看到同一目标；③ 落到场景 JSON 里就改这几个数。

① 两把尺子 — 同一根指向线，两种读数（以 A 星为例，星下点绝对方位 154.79°）

—— 上尺：kEciAbsolute 的刻度（0~360 固定在惯性系上，0° 在很远的地方，图里只画了 130~180 那一小段） 　·　—— 下尺：kNadirRelative 的刻度（0° 就钉在星下点方向上） 　·　｜ 竖直虚线 = 你配置的扫描起点（同一物理方向，上下两种读数） 　·　▲ 目标方位（key1 +8.5° / key2 -8.6°，也在下尺上）

② 三星编舞 — 为什么 B 星必须反向扫（速率 6°/s，视场 12°，扇区 ±15°）

左右两幅都是"从卫星往下看"的示意：卫星在顶上，地球盘角半径 8.69°，星下点=正下方。 key1 在 A 星眼里偏东 +8.5°、在 B 星眼里偏西 -8.6°（互为镜像）。 齐步走时两束光同升同降，永远一束在东一束在西 → 没有任何周期两星同时压着 key1； 镜像时两束光一升一降，相同周期各自压到 key1（绿色竖条），双星交会样本就出在这些周期。

③ 落到场景 JSON — 三颗星各改哪儿

字段A 星B 星C 星白话
scan_azimuth_referencekNadirRelative（不变）同左同左用哪把尺子：0° 钉在星下点
