# 验收指标与日志文件对应表（2026-08-24）

## 0. 这份文档怎么用

验收指标文档（雷达信号处理测试设计对照）里每条指标，交付时**写在哪个日志文件、按什么关键字搜**，本档一查即得。

三步定位：

1. 在 §3 主表按「原文主题 / 原文指标」找到行，读出**日志文件**与**搜索关键字**；雷达测试设计之外的指标查 §5（同一写法，按验收类分节）。
2. 打开对应日志文件（`log/` 目录，见 §1），按关键字搜 `[验收项：关键字]`，命中的每一行就是该指标一次记录。
3. 需要字段含义时看该行「行内字段」列；值是 `无` / `暂无` 时的判定见 §2。

一条原文指标一行；`[验收项：]` 里的名字**就是指标原文名**（交付日志不写派生/旁注），所以文档里的指标名可以直接当搜索词用。指标本身能否输出、口径依据，见对照档与清单，本档不重复。

| `integration_events.log`（示例层输出目录） | `examples`（component_attachment） | 性能计时真实墙钟（初始化 / 单步 / 模型加载 / 装配） | 运行示例即写（无需编译开关） | 装配与首次 Step |

注意：

- 五个验收日志开关**默认全 OFF**。没开开关就跑，文件不存在或为空——不是指标丢了，是没接线落盘。配置方式：CMake 配置期 `-DONEQ_ENABLE_RIR_ACCEPTANCE_LOG=ON` 等，按层各开各的。
- 两个 CSV 路径可用环境变量覆写：`ONEQ_RIR_ANTENNA_PATTERN_CSV_PATH` / `ONEQ_RIR_SCAN_PATTERN_CSV_PATH`；默认都落在运行工作目录的 `log/` 子目录。
- 重跑进程会**截断**旧验收文件（拿到干净结果）；同进程内会话重启是追加。
- `log/1q_library.log` 是库内调试日志（`ONEQ_ENABLE_FILE_LOG`），**不含验收指标**，别在里面找。
- 没跑到某层引擎（如纯传感器会话不跑融合），该层文件没有对应行，属正常，见清单「没跑到该层引擎按不能输出处理」。

## 2. 日志行格式（四段同一行）

所有验收日志同一格式：

```text
仿真时间=1.000s 仿真周期=1 [验收项：MTD增益] 验收内容：目标ID=1001 6.021dB
```

- 第 1 段 `仿真时间=`（s）、第 2 段 `仿真周期=`（周期号）：多文件对齐用——同一次运行里，各层文件按这两个字段对齐同一拍。
- 第 3 段 `[验收项：…]`：指标原文名，即本档主表的搜索关键字。
- 第 4 段 `验收内容：`：数值字段，或 `无` / `暂无`。
  - `无` = 本周期条件不满足（如无外部干扰单音、极化缺交叉极化/相位样本、无 cell），条件满足的周期会出真值；
  - `暂无` = 整项库内无实现（如计时三项），任何周期都是 `暂无`。

## 6. 排查备忘

- **文件空 / 不存在**：先查编译开关（§1，默认 OFF）；再查是否跑到了该层引擎（纯传感器会话不产融合/推演行）。
- **字段是 `无`**：本周期条件不满足，换有干扰/有极化样本的周期或场景（如 `rir_jammed_scan`）；不要当缺失项报。
- **字段是 `暂无`**：整项无实现（计时四项），去 `integration_events.log` 找墙钟。
- **多文件对拍**：用第 1/2 段（仿真时间/周期）对齐同一次运行的各层文件。
- **重跑丢数据**：进程重跑截断验收文件（设计如此，保干净结果）；归档请在跑完及时拷贝。
- 指标能否输出、为什么没有（MTI/MTD 主链、极化矩阵、CA-CFAR 等口径）：见对照档 §3 与 `docs/review/rir_mti_mtd_acceptance_sidecar_freeze_2026-08-22.md`、`docs/review/rir_polarization_l2_acceptance_sidecar_freeze_2026-08-22.md`，本档不重开讨论。
