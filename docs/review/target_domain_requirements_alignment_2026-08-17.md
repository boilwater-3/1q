# 目标域需求对齐与分层归属（目标状态识别 / 轨迹预测 / 发射点预测）

## 0. 结论速览（大白话）

- 新提的三项需求（目标状态识别含 UKF 与多目标关联、轨迹预测、发射点预测）**都不是
  sbirs_sensor 的能力**，是探测链下游的消费方：估计层吃量测、推演层吃航迹。
- 库内分层已成型：传感器（不动）→ 适配（SensorAdapters，已有）→ 估计（fusion 已做关联，
  轨迹滤波是其文档预留项）→ 推演（新建算法面）→ 决策（threat_assessment，已有）。
  规则已冻结进 `docs/common/contract.md` §目标处理分层契约。
- 三个需求澄清点的状态（2026-08-17 更新）：①"UKF"按无迹卡尔曼（Unscented）理解并实施
  ——需求语境下的 UKF 即无迹；UD 分解是数值稳定化实现细节，两者可组合而非二选一（§3.1）；
  ②"分离"已由需求方澄清为**数据关联**语义（非 CSO 图像级分辨），归估计层 fusion 已有能力
  （§3.2）；③发射点/轨迹预测必须按误差预算与观测条件谈指标——单源短弧段的物理可达精度有
  硬上限，先承诺指标必然违约（通俗解释见 §3.3）。
- 全库耦合审查：AR（航迹产品 + 识别回填）、ESR（threat_level 进 public 输出）有实质越层；
  SBIRS Estimated 后验外发、RIR 识别产品形态为冻结灰区；EOS/SAR/RIR 内部链/navigation/
  flight_dynamic/ECM 合规。全部登记为 TARGET-OQ-1..4，处置前不追溯回改。

## 3. 三个关键技术澄清

### 3.1 "UKF"裁定：按无迹卡尔曼（Unscented）实施（2026-08-17 已澄清）

- **需求语义**：滤波选型层面的"UKF"在目标跟踪需求语境里只有一种常规解读——无迹卡尔曼
  （sigma point 采样处理非线性量测/运动模型，无需雅可比）。UD 分解是**数值稳定化实现细节**，
  不会以"UDKF"之名出现在需求指标语言里。
- **真实天基红外链路的工程主流**：EKF 是基线（解析雅可比、计算量最小，本库 SBIRS 内部
  ATP 跟踪即 EKF）；对角度-only 弱可观测、弹道系数估计等强非线性问题，无迹类滤波
  （UKF/平方根 UKF）是文献与工程的常见升级路线；UD 分解（Bierman 一系，导航/GPS 遗产）
  的价值是给线性/EKF 提升数值稳健性，与"处理非线性"无关。
- **两者不互斥**：工程最佳形态是"无迹 + UD/平方根稳定化"的组合（SR-UKF 一类）。库内
  `Ekf*` + `Udkf*`（UD 稳定化）积木正好可按此组合复用，缺的只是无迹采样本身。
- **库内落地**：`src/common/estimation` 新增无迹 predictor/updater，对齐
  `IKalmanPredictor`/`IKalmanUpdater` 接口；命名避开 `Udkf*` 混淆（建议 `Unscented*`
  前缀或显式 `SquareRootUnscented*`）；SBIRS 内部 EKF（传感器行为建模）不因此改动。

### 3.2 "分离"裁定：数据关联语义（2026-08-17 已澄清）

需求方确认"分离"指量测到航迹的分离（哪个量测属于哪个目标），即**数据关联**——归估计层，
fusion 已实现（SBIRS 角度-only 走方位相干门），单传感器多目标是退化情形，无传感器侧新工作。

历史记录：审查时曾存在另一种解读——密集多目标分辨（CSO，两目标在像面上粘成一个斑，
需图像级处理）。该解读若未来被提出，属 sbirs_sensor boundaries 能力决策表的 defer 项
（需 PSF/像元/背景模型 + 独立物理真值的重开门流程），与本需求无关。

### 3.3 可观测性红线与误差预算（通俗版）

**什么是"误差预算"**：先从物理与量测条件推算"这批观测最好能做到多准"——把量测噪声、
动力学模型误差、起始状态不确定度逐项核算进最终产品的不确定度——再据此定验收指标。
反过来"先拍指标再找算法"是需求违约的常见来源：物理信息量不够，算法无法无中生有。

**单源短弧段为什么物理受限**：被动红外只测方向（方位/俯仰），不测距离——像用一只眼睛看
飞行物：方向看得准，距离靠猜。距离信息只能靠两条途径间接恢复：① 目标运动规律（弹道约束）
+ 足够长的观测弧段让滤波收敛；② 第二视角三角化（双星）或外部位置源（如 AR 航迹）融合。
观测时间越短（弧段越短），距离越不可观测。发射点/落点预测还叠加**回推放大**：把当前状态
误差沿弹道反向积分到起点，误差只会放大不会缩小——弧段越短、回推越远，放大越狠。

**量级示意（仅供建立直觉，非承诺；准确数字必须由可达性矩阵仿真给出）**：单星角度-only、
助推段几十秒弧段下，距离/发射点/落点误差可达公里级~数十公里级；双星三角化或与位置源融合
后方可望收敛到百米~公里级。"单源短弧段发射点误差 < 1 km"这类指标在物理上不可达。

**管理动作**：与需求方先对"源数 × 弧长 × 量测精度 → 可达 CEP/误差椭圆"可达性矩阵
（推演层 Stage A 交付物），据它谈指标与验收门；契约规则 6（产品必须携带不确定度）保证
这套诚实是结构性的，不依赖自觉。

## 5. 估计层 design.md 骨架（fusion 演进）

> 形态：扩展现有 `fusion` 模块为航迹层（其 boundaries 非目标 1 与变更规则 2 即此预留路径）。
> 立项时按四件套格式落 `docs/fusion/`，以下为骨架草案。

### design.md（定位/导航草案）

- **一句话**：fusion 是目标域**估计层**算法面——多源/单源多目标关联（已有）+ 航迹滤波 +
  航迹管理，输入泛型 `DetectionRecord`，输出带协方差的 `FusedTarget`（演进后含运动学状态）。
- **心智模型**：量测 → 关联 → 滤波 → 航迹生命周期 → 态势。关联与滤波是同一航迹管理状态机
  的两半，不拆两个模块。
- **演进边界**：第一版只加"逐航迹 UKF/EKF 滤波 + M/N 起始确认 + miss 删除"；Mahalanobis
  关联门、多模型（IMM）为后续项，各自走变更规则 2。

### boundaries.md（边界/非目标草案要点）

- 关联键边界（既有，冻结）：身份键调用方提供、0=无身份、合成键 ≥2^63。
- 新增：滤波原语单源 `src/common/estimation`，fusion 只实例化；估计层不感知传感器类型与
  坐标系（坐标对齐归调用方）；量测噪声模型 R 由调用方随 DetectionRecord 携带或按源通道
  配置——**不得**从传感器内部状态反推（连带 TARGET-OQ-3 的 Estimated 噪声语义裁定）。
- 非目标：不做推演（轨迹预测/发射点/识别归推演层）；不做威胁评分；不建事件总线。
- 变更规则：引入轨迹滤波前先冻结实现边界，并评估 `airborne_radar::signal::association`
  与 fusion 关联的复用/单源化路径（连带 TARGET-OQ-1 的关联两次问题）。

### data-flow.md（输入输出/状态所有权草案）

- 输入：`DetectionRecord`（演进：可选 per-record 量测协方差/噪声参数）+ `cycle`。
- 输出：`FusedTarget`（演进：+ 运动学状态均值/协方差、+ 航迹状态 tentative/confirmed/lost、
  + 最后更新时延）。
- 状态所有权：航迹状态机（滤波协方差、生命周期计数）全部引擎内；调用方零状态。
- 与上下游：上承 SensorAdapters，下接推演层（TrackState 输入）与 threat_assessment
  （fusion_confidence 证据侧，既有值级语义不变）。

### algorithms.md（算法登记表草案）

| 算法 | 状态 | 实现边界要点 |
|---|---|---|
| 四层关联（身份/KD-tree/方位相干/特征） | 已有冻结 | 不改语义；Mahalanobis 门为变更规则 2 后续项 |
| 航迹滤波（UKF/EKF per-track） | 新增候选 | 原语取自 common/estimation；角度-only 弱可观测必须体现在协方差中；确定性 replay |
| 航迹管理（M/N 起始、miss 删除） | 新增候选 | 与关联滑窗语义统一冻结；输出确定性按键排序 |
| 无迹滤波器（若 UKF=Unscented） | 新增候选（common/estimation） | sigma point 对齐 IKalman 接口；数值稳定下限沿用 kCovarianceFloor 语义桶 |

## 6. 推演层 design.md 骨架（新算法面，暂名 target_inference）

> 形态：新建独立算法面模块，模式完全照抄 threat_assessment 先例（泛型输入帧、纯函数或确定性
  增量、算法不感知传感器与坐标系、无 Session 形态）。命名待立项裁定。
> 立项前不得建目录（docs 结构守护只允许既有模块一级目录）。

### design.md（定位草案）

- **一句话**：target_inference 是目标域**推演层**算法面——消费估计层航迹状态（带协方差），
  产出轨迹预测、发射点/落点回推、目标类型概率，全部携带误差预算。
- **心智模型**：态势 → 推演。每个产品 = 一个纯函数面：`(TrackState[], 配置) → 带不确定度的结论`。
- **关键定位**：与 RIR 的关系先裁定（TARGET-OQ-4：装备级识别豁免形态 + 知识库/原语复用
  边界）；与 threat_assessment 的分工：推演层出"是什么/去哪/从哪来"，决策层出"多危险"。

### boundaries.md（边界草案要点）

- 输入为泛型航迹帧（位置/速度/协方差/类型概率证据），不引用 fusion/传感器类型（值级语义
  耦合按 threat_assessment 的 `fusion_confidence` 先例冻结）。
- 弹道运动模型（中心引力 + 气动阻力 ODE）私有于本模块；不依赖 JSBSim/flight_dynamic。
- 每个产品必须携带误差预算（规则 6）；不出口无不确定度的点估计。
- 非目标：不做关联/滤波（估计层职责）；不做威胁评分（决策层职责）；不建 Session/事件总线。

### algorithms.md（登记表草案）

| 算法 | 要点 |
|---|---|
| 弹道前向外推 | 估计状态 + 弹道 ODE 前向积分；输出预测位置 + 时变误差椭圆 |
| 发射点回推 | 反向积分至发射假设满足（高度/速度判据）；输出发射点误差椭圆；单源弱可观测场景须给出可达性说明 |
| 落点预测 | 前向积分至落点判据；同上误差预算 |
| 目标类型识别 | 特征帧 → 类型概率（知识库来源待立项）；输出对齐 threat_assessment 类型概率输入 |

### data-flow.md

按 threat_assessment 先例可省略（若维持无状态函数面）；若发射点回推需要跨周期航迹历史，
