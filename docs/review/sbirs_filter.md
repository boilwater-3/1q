# 天基红外传感器 SBIRS 实现计划

Status: draft
Authority: historical implementation plan draft

本文是 SBIRS 模块的早期实现计划草案。权威设计已迁入 `docs/space_based_infrared_sensor/design.md`；本文第 0 节
"与 filter.md 的差异"记录了对本草案的审查修正（迁移源头、状态机统一、地球遮挡补充、
契约注册、气象衰减模型）。本草案保留作为历史记录，不再作为当前设计引用。

---

## Summary

- 目标：在当前红外传感器模型基础上，扩展为独立的天基红外传感器 SBIRS 模块。
- 命名：内部和新增模块使用 `SBIRS` / `Sbirs*`，对应 **Space-Based Infrared System**。
- 接口约束：**当前输出接口保持不变，输出字段与现有红外传感器保持一致**；WFOV、NFOV、交接、捕获、多目标管理等状态先作为内部状态，不扩展对外输出结构。
- 核心流程：WFOV 宽视场发现目标；第一次进入 NFOV 时，使用 NFOV 捕获算法捕获 WFOV 输出的带误差位置；若捕获成功，后续使用目标真值位置持续捕获/跟踪；若第一次捕获失败，回到 WFOV 继续搜索。

## Key Changes

- 新建独立 SBIRS 模块：
  - 公开目录：`include/1q/sbirs_sensor`
  - 实现目录：`src/sbirs_sensor`
  - 命名空间：`sbirs_sensor`
  - 类型前缀：`Sbirs*`
- SBIRS 不在公开头文件中暴露 `electro_optical_sensor`、`Eos*`、`1q/electro_optical_sensor/...`。
- 但 SBIRS 的输出接口保持与当前红外传感器一致：
  - 输出仍是检测记录列表语义。
  - 字段保持：目标/检测 ID、距离、方位角、俯仰角、红外 SNR、可见光 SNR、融合 SNR、是否探测成功。
  - 不新增公开的 cueing/acquisition/tracking 输出字段。
- 内部新增状态：
  - `WideSearch`
  - `NarrowFirstAcquisition`
  - `TruthLockedTracking`
  - `ReturnToWideSearch`
  - `Ended`

## Implementation Path

- 阶段 1：SBIRS 独立接口与代码骨架
  - 从当前 `space_based_infrared_sensor` 迁移出独立 `sbirs_sensor` 模块。
  - 复制红外传感器中辐射、传播、噪声、环境、SNR 计算能力，改为 SBIRS 自有命名空间和类型。
  - 保持输出结构与现有红外传感器一致，不新增对外输出字段。

- 阶段 2：WFOV 宽视场多目标搜索
  - 每个周期对输入场景中的所有目标执行 WFOV 扫描判断。
  - 对进入 WFOV 的目标计算带误差观测位置：方位角、俯仰角、距离。
  - 对每个目标计算 SNR 和检测阈值。
  - 满足 WFOV 检测条件的目标进入候选列表。
  - 支持多目标：内部以 `target_id` 建立候选状态表，每个目标独立维护 WFOV 发现状态。

- 阶段 3：WFOV 到 NFOV 的首次捕获
  - 对 WFOV 已发现的目标，使用 WFOV 输出的**带误差位置**作为 NFOV 首次捕获输入。
  - NFOV 捕获算法使用带误差方位/俯仰和当前 NFOV 搜索窗口判断目标能否被捕获。
  - 首次 NFOV 捕获成功条件：
    - 目标仍存在于输入场景；
    - WFOV 带误差位置落入 NFOV 搜索窗口；
    - NFOV SNR 或捕获门限满足要求。
  - 若首次 NFOV 捕获失败：
    - 不进入真值锁定；
    - 清除该目标本次交接状态；
    - 目标回到 WFOV 搜索/候选流程，等待后续周期重新发现和交接。

- 阶段 4：NFOV 真值锁定持续跟踪
  - 对首次 NFOV 捕获成功的目标，后续周期进入 `TruthLockedTracking`。
  - 后续不再使用 WFOV 带误差位置重新捕获，而是使用目标真实位置计算 NFOV 指向和检测输出。
  - 只要目标仍存在于输入场景，且传感器开启，就认为 NFOV 能持续捕获/跟踪该目标。
  - 输出仍按现有红外传感器检测记录格式生成：角度、距离、SNR、是否探测成功。
  - 可在输出测量值上叠加误差，但误差不影响内部真值锁定状态。

- 阶段 5：多目标状态管理
  - 每个目标独立维护状态：
    - 未发现；
    - WFOV 候选；
    - 等待 NFOV 首次捕获；
    - NFOV 首次捕获失败；
    - NFOV 真值锁定；
    - 目标消失。
  - 同一周期允许多个 WFOV 候选目标。
  - NFOV 资源第一版采用单目标锁定策略：优先锁定最高优先级目标。
  - 优先级默认规则：
    - 已真值锁定目标优先级最高；
    - 新候选按 SNR 从高到低；
    - SNR 相同按距离从近到远；
    - 仍相同按 `target_id` 从小到大。
  - 已锁定目标消失后，NFOV 释放资源，回到 WFOV 中选择下一个候选目标。

- 阶段 6：误差模型与后续扩展
  - WFOV 输出位置必须带误差，用于首次 NFOV 捕获判定。
  - 误差来源包括：姿态误差、指向误差、像元定位误差、大气折射误差、动态滞后误差。
  - 后续可扩展为多 NFOV 通道、多目标同时真值锁定、图像级 TBD、模板匹配、EKF 跟踪，但第一版不实现。

## Output Contract

- 对外输出接口保持与当前红外传感器一致。
- 不新增公开字段表达 WFOV/NFOV/捕获/跟踪状态。
- 内部状态仅用于决定当前周期哪些目标输出检测记录。
- 输出规则：
  - WFOV 阶段：输出 WFOV 检测成功目标的检测记录。
  - NFOV 首次捕获成功周期：输出 NFOV 捕获后的检测记录。
  - NFOV 真值锁定周期：持续输出锁定目标的检测记录。
  - NFOV 首次捕获失败周期：不输出该目标 NFOV 成功记录，目标回到 WFOV 流程。
- 如需调试 WFOV/NFOV 状态，后续单独增加 debug view，不影响正式输出接口。

## Test Plan

- WFOV 搜索测试：
  - 多目标场景下，仅 WFOV 视场内且 SNR 达标的目标进入候选。
  - WFOV 带误差位置生成稳定且误差可控。
- NFOV 首次捕获测试：
  - WFOV 带误差位置落入 NFOV 搜索窗口时，首次捕获成功。
  - WFOV 带误差位置超出 NFOV 搜索窗口时，首次捕获失败并回到 WFOV。
  - 首次捕获失败目标后续能再次被 WFOV 发现并重新尝试 NFOV 捕获。
- 真值锁定测试：
  - 首次 NFOV 捕获成功后，后续周期使用目标真实位置持续输出。
  - 真值锁定目标只要仍在输入场景中，不因测量误差丢失。
  - 目标从输入场景消失后，锁定状态结束。
- 多目标测试：
  - 多个 WFOV 候选同时存在时，按 SNR、距离、target_id 选择 NFOV 首次捕获目标。
  - 已锁定目标优先于新候选目标。
  - 锁定目标消失后，系统能切换到下一个候选目标。
- 接口回归测试：
  - 当前红外传感器输出接口不变。
  - SBIRS 输出字段与现有红外传感器保持一致。
  - 原 EOS 模块构建和测试不受影响。

## Assumptions

- 第一版 NFOV 资源按单目标锁定处理，不实现多个窄视场同时跟踪。
- 第一次 NFOV 捕获必须使用 WFOV 输出的带误差位置；捕获成功后才允许使用目标真值位置持续跟踪。
- 捕获成功后的真值锁定只受目标是否存在、传感器是否开启影响，不受后续测量误差影响。
- 输出接口保持现有红外传感器格式，不新增公开字段；WFOV/NFOV 状态仅内部使用。
- EOS 原模块只作为迁移参考，不作为 SBIRS 对外集成依赖。
