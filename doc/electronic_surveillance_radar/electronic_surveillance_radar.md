# 1.3.2.2 电子侦察设备组件

## 1.3.2.2.0 需求定位与范围

本组件面向真实电子侦察场景建模，目标是建立一个符合电子支援侦察基本机理的仿真模块，而不是简单基于真值辐射源列表做可见性过滤。组件应以"接收机观测链路"为中心，完整描述从电磁信号进入接收机，到形成侦察报告、威胁告警和可选定位结果的处理过程。

本需求基线的能力边界如下：

- 基线对象为雷达辐射源侦察，即 RESM / ELINT 类能力。
- 通信辐射源侦察可作为后续扩展能力，不纳入首版基线主流程。
- 被动雷达导引头属于独立任务构型，可复用本组件的接收、测向和识别底层能力，但不与平台级电子侦察主流程混写为同一输出契约。
- 本组件既支持高保真接收机级仿真，也支持任务级简化仿真，但两种精度档位必须遵循相同的观测语义，不允许将真值标签直接作为传感器输出。

## 1.3.2.2.1 接口层能力

接口层是电子侦察设备组件与外部仿真系统交互的标准化边界，负责设备初始化、场景真值接入、环境快照接入和周期驱动控制。接口层输入的是仿真系统已知的场景真值和平台状态，接口层输出的是供组件内部使用的周期观测条件，而不是直接输出侦察结论。

本层级主要负责以下功能：

- 装备参数初始化：接收侦察设备配置参数，包括接收频段、瞬时带宽、扫描方式、驻留时间、接收机噪声系数、灵敏度、动态范围、测向体制、天线方向图、极化特性和信号处理精度档位。
- 平台状态注入：接收侦察平台当前位置、姿态、速度、挂载方位和任务工作模式，为视线分析、波束指向和时间同步提供基础条件。
- 场景真值接入：接收辐射源真值列表，包括发射机位置、姿态、工作频率、功率、脉宽、重频、扫描规律、调制样式和工作状态。该输入仅用于生成接收机可观测信号，不可越级作为侦察结果直接上报。
- 环境与传播条件接入：接收地形遮蔽、地球曲率、大气衰减、天气、地表反射、多径和外部电磁环境参数，用于计算接收链路与观测退化。
- 干扰与复杂电磁环境接入：接收压制式噪声、宽带阻塞、转发式欺骗和同频密集辐射环境参数。不同类型干扰必须以不同作用机理进入后续接收链路，不得统一简化为单一背景功率。

### 1.3.2.2.1.1 设备参数配置与周期驱动模块

本模块是电子侦察设备组件的唯一外部入口，负责以下职责：

- 完成设备实例化、通道配置、天线与测向体制装配。
- 在每个仿真周期接收平台状态、场景真值和环境快照。
- 将场景真值转换为内部信号生成层的输入，而不是直接下发给识别层。
- 管理工作模式切换，包括全向搜索、扇区搜索、定向监视和告警优先模式。

## 1.3.2.2.2 接收与观测层能力

接收与观测层是电子侦察组件的物理入口，负责把场景中的辐射源真值转换为接收机可见的信号观测。该层输出应为接收机观测记录，例如截获脉冲、测得的到达方向、频率、脉宽、幅度和时间标记，而不是直接输出"已识别某平台某设备"。

本层级主要负责以下功能：

- 可视与可截获判定：依据平台姿态、天线指向、扫描时序、频段覆盖、动态范围、传播损耗和遮蔽条件，判定当前周期哪些辐射活动进入接收机视场并可被截获。
- 接收机效应建模：建模噪声底、灵敏度门限、前端饱和、带宽截断、幅相测量误差、频率测量误差和时间戳误差。
- 测向观测生成：依据测向体制生成方位角、俯仰角或仅方位线观测，并附带统计误差和置信度。测向精度可与接收信噪比、天线基线、波束宽度和算法体制相关联。
- 脉冲/信号观测生成：对脉冲雷达产生 PDW 类观测记录，至少包含时间到达、载频、脉宽、幅度、到达方向和测量误差；对连续波或特殊体制雷达应保留扩展字段。

### 1.3.2.2.2.1 可截获与扫描调度模块

本模块负责根据接收机扫描规律、驻留时间和视场限制，判断信号是否在当前时间窗内进入接收链。对于扫描雷达发射源，应考虑发射机波束是否扫到侦察平台；对于侦察设备自身，也应考虑是否在当前接收扇区内完成有效截获。该模块的输出是"接收到的候选观测"，而不是"场景内全部辐射源"。

### 1.3.2.2.2.2 接收机观测生成模块

本模块对候选观测生成带误差的接收记录：

- 对脉冲雷达，输出 PDW 风格记录。
- 对连续波或低截获概率体制，输出与其体制相匹配的窄带/宽带观测摘要。
- 对噪声压制、阻塞干扰，主要体现为灵敏度下降、丢截获和测量误差增大。
- 对欺骗式干扰和密集同频辐射，主要体现为额外假观测、参数污染和后续分选歧义，而不是仅增加背景噪声。

## 1.3.2.2.3 信号处理与识别层能力

信号处理与识别层是电子侦察主处理链，负责把接收机观测整理成可理解的辐射源假设和威胁结果。本层必须显式包含"观测整理 -> 分选/聚类 -> 模式识别 -> 轨迹化管理"的过程，不能省略为对真值目标逐个做门限判决。

本层级主要负责以下功能：

- 观测预处理：对接收记录做去噪、时间排序、量测归一化和异常观测剔除。
- 脉冲分选与去交错：依据时间到达、频率、脉宽、方位和幅度等特征，将混杂观测拆分为候选发射源序列。
- 工作模式识别：从候选发射源序列中识别搜索、跟踪、制导、频捷、脉组或其他工作模式，并形成模式切换历史。
- 威胁评估：综合辐射源类型、工作模式、测向稳定性、与己方相对几何关系和历史行为，输出威胁等级。
- 发射源轨迹化管理：对同一辐射源的历次观测进行关联与时间连续性维护，形成辐射源轨迹或辐射源假设集合。

### 1.3.2.2.3.1 观测预处理模块

本模块负责对接收机观测记录进行统一化处理，包括时间对齐、离群点剔除、重复脉冲合并和质量标注，为后续分选与识别提供稳定输入。

### 1.3.2.2.3.2 脉冲分选与辐射源聚类模块

本模块依据观测特征执行脉冲分选、去交错与聚类，形成"候选辐射源序列"。这是电子侦察区别于简单链路判决的关键步骤。在多辐射源密集场景下，该模块应允许发生漏分选、错分选和聚类歧义，并以置信度形式向上游暴露不确定性。

### 1.3.2.2.3.3 辐射源识别与威胁评估模块

本模块基于候选辐射源序列执行以下操作：

- 根据频率、脉宽、重频、扫描规律、测向历史和调制特征做发射源类别识别。
- 输出"识别假设"而非强制唯一结论，支持多个候选型号及其置信度排序。
- 结合任务规则和战术知识，将发射源工作模式映射为威胁状态，例如搜索、跟踪、制导、压制或未知。

## 1.3.2.2.4 空间解算与定位层能力

空间解算与定位层负责把测向观测转换为更高层的空间态势信息。该层输出应遵循被动侦察规律：

- 单平台单次观测通常产生方位线或角域观测，不应默认直接得到目标精确地理坐标。
- 单平台多时刻机动解算可支持方位交汇或滤波定位。
- 多平台协同时可支持基于多条方位线或时差/频差的被动定位。

本层级主要负责以下功能：

- 角度观测解算：输出方位、俯仰及其协方差。
- 方位线维护：对可疑辐射源形成方位线历史序列。
- 被动定位：在满足几何条件时进行单平台机动定位或多平台协同定位，并输出定位误差椭圆。
- 不可定位状态管理：当观测条件不足时，明确输出"仅有方位信息"或"定位不收敛"，而不是伪造坐标结果。

### 1.3.2.2.4.1 测向解算模块

本模块以接收体制、波束参数、信噪比和几何条件为输入，输出方位角、俯仰角和误差统计量。允许根据不同测向体制切换误差模型，例如扫描测向、振幅比较测向和干涉仪测向。

### 1.3.2.2.4.2 被动定位模块

本模块仅在观测条件满足时输出地理定位结果。对于首版基线，允许先支持：

- 单平台多时刻机动交汇定位。
- 双平台或多平台方位交汇定位。

对 TDOA/FDOA 等更复杂定位方法，可预留扩展接口，但不应在首版需求中写成默认能力。

## 1.3.2.2.5 数据访问与输出层能力

数据访问层是电子侦察设备组件的标准输出边界，负责区分"传感器观测输出"、"识别推断输出"和"真值评估输出"三类数据，避免把真值标签伪装成侦察结果。

本层级主要负责以下功能：

- 观测输出：输出接收机观测记录、PDW 记录或聚类后的辐射源候选记录，供外部系统复核或后处理。
- 侦察结果输出：输出辐射源假设、工作模式、威胁等级、测向结果、可选定位结果和对应置信度。
- 真值评估输出：仅供仿真统计和算法评估使用，记录内部观测与场景真值的关联关系，不得作为外部战术接口默认字段。
- 历史缓存：维护辐射源历史、方位线历史和识别状态历史，支持跨周期连续侦察。

### 1.3.2.2.5.1 观测输出模块

本模块输出的内容以传感器视角组织，至少包括：

- 观测记录编号与时间戳。
- 测得的频率、脉宽、幅度、方位、俯仰及误差。
- 观测质量、置信度和是否疑似受干扰污染。

### 1.3.2.2.5.2 侦察结果输出模块

本模块输出的内容以辐射源假设视角组织，至少包括：

- 内部辐射源轨迹编号。
- 发射源类别和工作模式假设集合。
- 方位线或定位结果及其精度描述。
- 威胁等级、稳定度和最近观测时间。

本模块不得默认输出平台编号、设备编号和唯一真值型号。若仿真场景需要评估识别正确率，应通过独立的真值评估输出通道提供。

### 1.3.2.2.5.3 真值评估与统计模块

本模块仅供离线评估和算法统计使用，记录以下内容：

- 观测记录与场景真值发射源的内部关联。
- 漏截获率、错分选率、误识别率、虚警率和定位误差统计。
- 干扰环境下的性能退化指标。

## 1.3.2.2.6 精度档位与工程约束

为兼顾真实性与仿真效率，组件至少支持两档精度：

- 高保真档：显式建模接收观测、测量误差、分选歧义、误识别和定位不确定性。
- 任务级简化档：允许降低观测粒度，但仍需先生成"传感器观测摘要"再进入识别链，不得跳过观测语义直接从真值源生成侦察结论。

本组件必须满足以下工程约束：

- 不允许将场景真值中的平台编号、设备编号直接写入对外侦察结果。
- 不允许把全部干扰统一抽象成单个背景功率项。
- 不允许把通信侦察、平台级电子侦察和被动导引头闭环跟踪写成一套未区分的统一输出模型。
- 所有侦察结论必须带置信度或误差描述。

## 1.3.2.2.7 首版交付定义

首版真实电子侦察模块建议以"平台级雷达辐射源侦察"为交付边界，包含以下最小闭环：

1. 场景真值发射源输入。
2. 可截获判定与接收机观测生成。
3. PDW 风格观测输出。
4. 脉冲分选与候选辐射源聚类。
5. 发射源类别识别、工作模式识别和威胁评估。
6. 方位线输出，定位能力可先支持单平台多时刻交汇。
7. 观测输出、侦察输出和真值评估输出三通道分离。

在首版完成前，不建议将通信侦察和被动雷达导引头合并进同一需求基线。

## 1.3.2.2.8 首版工程基线（2026-03 已实现）

当前代码基线已落地 `electronic_surveillance_radar` 首版闭环，实现范围与本需求文档保持一致，采用最小公共接口 + 内部可替换算法组件的工程组织方式。

### 1.3.2.2.8.1 公共接口与类型

已冻结以下公共类型与接口（均位于 `include/1q/electronic_surveillance_radar`）：

- 输入与真值：`EsrCycleInput`、`EmitterTruthState`。
- 观测与侦察输出：`EmitterObservation`、`EmitterHypothesis`、`EsrOutputFrame`。
- 环境接口：`IEsrEnvironmentService::BeginCycle/SampleEnvironment`。
- 流水线接口：`IInterceptPipeline::RunCycle`。
- 会话入口：`EsrSession::Step/StepWithResult`。

### 1.3.2.2.8.2 固定周期执行顺序

控制器按如下固定顺序执行单周期：

1. `BeginCycle` 冻结环境场景；
2. `Pipeline.RunCycle` 生成观测、假设与评估关联；
3. `OutputManager.Build` 组装三通道输出；
4. 缓存 latest frame 供 Session 读取。

### 1.3.2.2.8.3 三通道输出约束

- 观测通道：接收机观测（AOA、RF、PW、幅度、SNR、质量、受扰标记）。
- 侦察通道：辐射源假设（类别候选、模式、威胁、置信度、最近命中周期）。
- 真值评估通道：观测-真值关联仅用于评估。

侦察通道不包含真值直通字段；真值标识仅存在于评估通道。

### 1.3.2.2.8.4 首版内核算法组件

已在 `src/electronic_surveillance_radar/intercept` 落地以下组件并纳入测试：

- `BandClassifier`：按载频映射雷达频段。
- `ScanPatternGenerator`：按扫描起点、顺序、步进生成波束序列。
- `InterceptGate`：联合判定通视/视场/频段覆盖/距离/动态范围。
- `JammingAggregator`：按目标频段聚合干扰功率与风险。
- `AngleErrorModel`：`sigma(beamwidth,snr)` 与误差采样分离。
- `BoundarySearchSolver`：二分搜索最远可截获边界。

### 1.3.2.2.8.5 当前明确不在首版范围

- 通信侦察主链。
- TDOA/FDOA 定位链路。
- 多线程并行优化。
